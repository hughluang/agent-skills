# 业务测试

围绕当前工作区一组相关变更，在隔离环境中执行真实业务操作，核对业务预期、应用反馈与最终状态。依据项目实际情况选择运行入口、测试工具和取证方式。

## 启动确认

进入主流程前，与用户确认以下内容；本轮对话中已明确且仍适用的决定直接沿用。

- **测试范围**：明确待测变更、涉及业务和预期覆盖边界。用户未指定时，先识别最近一组相关变更及其业务，再请用户确认。独立业务分别组织流程，共享依赖纳入关联验证。
- **角色分配**：逐项确认是否委派子 agent 及所用模型，未委派的职责由主 agent 承担。根据用户需要调整角色；模型选择以当前工具实际支持的能力为准，不支持时说明限制并确认替代安排。

| 角色 | 职责 |
| --- | --- |
| 测试环境搭建 | 环境辨认、搭建或复用、待测代码加载、身份与数据准备、就绪交接、恢复与清理 |
| 业务场景设计 | 依据业务约定设计完整流程，梳理依赖、状态变化及设计疑点 |
| 测试用例设计 | 将业务流程转为可执行、可判定的用例 |
| 测试执行员 | 操作运行中的应用，核对结果并记录证据 |

主 agent 负责阶段验收、职责衔接和结果汇总。每次派发提供任务范围、业务依据、输入产物、可操作资源、受保护资源、恢复方案和交付标准。发现执行偏差时，先修正前提或方法，再继续执行。

## 主流程

### 1. 建立测试依据

阅读确认范围内的变更、相关实现及产品或业务说明，整理为「业务约定」：明确操作者、适用前提、预期结果和应持续成立的不变量，并记录来源。实现用于理解当前行为，预期以业务约定为判定依据。

依据缺失或相互冲突时，记录待确认事项；影响结果判定或操作安全的事项先请用户澄清，其余部分可继续测试。

完成标准：范围内各项业务的依据及缺口均已记录，可执行部分有可追溯的判定依据，待确认部分已明确所需补充信息。

### 2. 准备环境与设计流程

以下工作可并行开展，按流程分别交付和验收。

- **环境准备**：环境搭建角色按「运行环境」准备资源，完成就绪交接。
- **流程设计**：场景设计角色为每条业务写明操作者、前提、动作顺序、状态变化、可见结果和数据落点，标明依赖及共享状态，将设计疑点关联到对应步骤。

完成标准：环境具备可核验的就绪证据；每条已交付流程均能描述从初始条件到最终结果的完整过程。流程交付后即可进入用例设计。

### 3. 设计用例

为已交付流程设计用例，赋予稳定编号并关联具体步骤。每条用例写明业务依据、初始状态、操作顺序、可判定的期望、取证方式及恢复要求。

| 类型 | 验证重点 |
| --- | --- |
| 正向 | 满足前提时，完整流程及最终结果符合约定 |
| 逆向 | 前提不满足或操作受限时，拒绝方式、状态保留与反馈符合约定 |
| 误操作 | 偏离预期操作顺序或次数时，应用仍维持约定的不变量，并提供与实际状态一致的反馈 |

根据变更影响和业务风险选择覆盖点；不适用的类型说明理由。共享状态及流程依赖体现在执行顺序和数据安排中，使每条用例的前提可建立、结果可归因。

完成标准：每条流程均有覆盖关键结果和相关不变量的用例，预期可判定，前提可复现，覆盖缺口已注明。

### 4. 执行与取证

主 agent 确认环境就绪，并验收待执行批次的流程和用例后，执行员通过应用的实际业务入口发起操作，逐项对照预期、即时反馈和最终状态。涉及持久化的结果同时核对数据落点；界面操作遵循「界面验证」。

- 每条用例记录实际前提、执行步骤、结果及证据。静态分析和模拟结果作为辅助材料，与真实执行证据区分。
- 环境准备、加载等待和业务执行分别记录。遇到阻塞时，保留已完成结果，注明受影响用例及继续执行所需条件。
- 需要临时观测时，采用可识别的统一标记，记录观测范围、未覆盖路径及撤销方式，保持业务行为不变。
- 发现范围内尚未覆盖的行为时，补齐对应流程和用例后执行；涉及范围扩展时先取得用户确认。
- 发生超出授权边界的状态变化时，暂停相关操作，按恢复方案处理并核验结果，再记录影响；恢复需要额外授权时先请用户确认。

完成标准：计划内用例均按「结论与异常分级」记录执行状态；结论有证据支持，待确认、阻塞和未执行项有原因及影响范围。

### 5. 报告与收尾

按「报告」汇总结果。环境搭建角色协调收尾，各角色交还自己引入的临时资源；测试完成或中途终止时，均按实际变更清单处理：

- 按恢复方案还原测试数据，回收临时身份及授权；需要保留的数据记录用途、隔离方式和后续处理责任。
- 撤销本次测试引入的临时源码改动与观测配置，保留用户原有改动。需要重新加载的测试进程按「重启与加载」处理，并核验恢复后的运行态。
- 删除含秘密的临时文件，保留脱敏测试产物。
- 停止本次创建且已无用途的进程。仍有使用者或归属不明的资源，确认处置方式后再操作。
- 保持代码提交为独立授权事项，由用户决定是否提交。

完成标准：总报告包含测试结果与收尾证据，保留资源、未恢复事项及所需后续行动均有明确说明。

## 运行环境

### 隔离与操作边界

使用与真实用户业务隔离、且运行已确认待测代码的环境。结合项目说明、资源配置、进程信息、访问入口及数据去向确认资源用途；运行用户或端口仅作为识别线索。

| 资源 | 操作原则 |
| --- | --- |
| 生产或受保护资源 | 保持原状，业务测试通过已确认的隔离资源完成 |
| 被测应用 | 在用户确认的范围内操作具体实例及其配套测试资源 |
| 共享基础设施 | 保留共享服务及其他使用者状态，仅操作已确认隔离的测试数据与命名空间 |

记录允许操作的资源、受保护资源和数据边界。归属、隔离性或操作影响不明确时，先请用户确认。新增基础设施、安装系统依赖或改变启动配置前，说明必要性及影响并取得同意。

### 搭建与就绪交接

按项目现有说明搭建或复用环境，提交以下信息并归档证据：

- 启动方式、工作目录、运行身份及访问入口，以及适用的进程、端口或实例标识。
- 可操作资源、受保护边界及共享依赖的隔离方式。
- 测试身份、数据准备情况、凭证配置来源及恢复方案，敏感内容脱敏。
- 能将当前运行实例与待测代码对应起来的加载证据，以及通过实际入口完成的就绪请求和结果。

身份与数据可用、依赖满足、代码对应关系可核验、就绪请求通过且交接信息齐全，视为环境就绪。就绪检查用于确认执行条件，业务结果仍由对应测试用例判定。

### 重启与加载

重启前记录目标实例的启动命令、工作目录、运行身份、端口及必要配置，精确定位其进程和产物边界。按已确认方式重启，保留其他实例及共享服务，并用真实请求核验待测代码已加载。

需要构建或按需编译时，先触发目标入口加载，结合完成日志、进程活动和响应内容判断状态：

| 状态 | 判定与处理 |
| --- | --- |
| 就绪 | 构建或加载已完成，目标入口可响应，待测代码对应关系已确认，可进入业务操作 |
| 进行中 | 有可观察的加载进展，继续等待并记录环境状态 |
| 异常或状态不明 | 结合项目正常启动特征和依赖状态补充证据，明确失败环节后采取有针对性的恢复措施 |

恢复仅作用于已授权的测试实例和可再生产物。需要重建时，先停止对应写入进程，确认产物由该实例独占，再清理并重新生成。每份构建产物保持单一写入者，源码调整与当前构建串行安排。

页面切换后的等待按目标入口重新判断。不同访问端表现不一致时，对照它们实际连接的实例、网络路径和响应，定位差异后再继续业务判定。

### 凭证与数据

- 从被测环境对应的配置或授权渠道获取凭证，确认身份权限与目标数据环境匹配。
- 派发说明和测试产物只记录凭证来源及脱敏信息。秘密确需落盘时，使用产物目录外、访问权限受限的临时文件。
- 测试数据使用可识别标记，记录所属用例、隔离边界、初始状态和恢复方法。恢复方案同时适用于预期写入与意外成功的写入。

## 界面验证

使用当前环境中可用的浏览器和驱动，工具选择以能够真实完成用户操作并保留证据为准。

- 等待目标控件可操作，结合当前界面语言、可见文案和上下文定位目标。
- 通过与用户交互一致、能触发应用实际事件处理的输入方式操作，核对界面接受的值。
- 动作后及时记录提示及截图；对需要跨加载保留的状态，再通过刷新或重新进入核对界面，并验证对应持久化结果。被拒绝操作的界面状态按业务约定核验。
- 依据业务目标评估交互是否易于理解、反馈是否与实际状态一致；布局变更覆盖相关视口下的可用性并留存截图。

用例证据应包含已完成的业务动作及其反馈，加载画面记录为环境状态。对阻挡操作的开发辅助界面，先保留证据，确认关闭不影响待测业务后再继续；依据其实际影响区分环境观察与业务缺陷。

## 复测

沿用本轮仍适用的范围、角色安排和产物目录。检查上一轮后的代码与环境变化，更新受影响的业务依据、流程和用例；需要扩展范围时重新确认。

优先复测上次异常，再验证本次变更影响的相关路径。保留历史结论，追加本轮执行证据。异常关闭以原复现条件下符合预期、且相关不变量保持成立为依据，涉及界面和持久化的结果分别核验。

## 报告

全部测试产物统一保存到当前系统可写的临时目录下 `biztest-<主题>/`，总报告为 `report.md`；用户指定位置时使用该位置。流程、用例、截图及日志摘录按需单独保存，由总报告以可访问链接引用。产物语言与用户本轮对话一致，保留内容均已脱敏。

### 结论与异常分级

用例通过或失败以业务约定和真实执行证据为依据。执行条件缺失记为阻塞，尚未开展记为未执行；已执行但依据冲突或证据不足时记为待确认，明确所缺信息。约定未覆盖的行为记为观察，环境问题单独记录；补充依据和证据后再更新相应结论。

对已确认缺陷，结合影响范围、结果正确性、可恢复性和绕过方式分级。同一缺陷符合多个等级时采用最高等级，并写明分级理由；绕过方式须经验证且在业务上可接受。

| 等级 | 判定标准 |
| --- | --- |
| P0 | 关键业务大范围不可用，或核心业务状态受到严重破坏，且缺少可靠恢复或控制影响的手段 |
| P1 | 未达到 P0，但关键流程无法完成、关键结果错误或业务不变量被破坏，且无可接受的绕过方式 |
| P2 | 未达到更高等级，但影响业务完成或结果正确性；影响限于局部流程或特定条件，或可通过经验证的可接受方式绕过 |
| P3 | 业务结果和不变量均正确，缺陷仅影响呈现、说明或非阻断性交互体验 |

### 总报告模板

```markdown
# <主题>

## 过程
测试范围、业务依据及来源、角色分配、执行概况和操作边界遵守情况。

## 环境
搭建或复用方式、启动与访问信息、可操作资源、隔离方式、身份与数据准备、就绪证据。存在阻塞时注明原因、影响范围和继续条件。

## 流程与覆盖
流程及用例文档链接、依赖关系、覆盖依据、未覆盖部分及理由。

## 结果
| 用例 | 所属流程及步骤 | 期望 | 实际 | 状态 | 证据 |
| --- | --- | --- | --- | --- | --- |

## 缺陷
按实际存在的等级汇总；无已确认缺陷时明确说明。
每条记录编号、关联用例、判定依据、复现条件与操作、预期与实际差异、影响及分级理由、绕过或恢复方式、证据和复测状态。

## 观察与待确认
分别记录业务观察、环境问题及依据待确认事项，说明影响、已有证据和所需后续行动。

## 收尾
负责人、数据恢复与身份回收、进程停止或保留、秘密文件删除、临时改动及运行态恢复结果，以及遗留事项与处置安排。
```
