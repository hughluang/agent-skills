# 业务测试

围绕当前工作区的一组集中变更，验证其业务流程、实际反馈和持久化结果。根据项目确定技术栈、运行入口和测试方式。

## 启动确认

进入主流程前，与用户确认测试范围及角色分配；本轮对话已确认的内容可沿用。

**范围**：以用户指定的变更和业务为准。未指定时，识别最近一组相关变更及其业务，请用户确认。彼此独立的业务分别测试。

**角色**：逐项确认是否委派子 agent，以及所用模型；未委派的职责由主 agent 承担。用户可增补角色。

| 角色 | 职责 |
| --- | --- |
| 测试环境搭建 | 环境辨认、搭建或复用、代码加载、凭证与数据准备、就绪交接、恢复与清理 |
| 业务场景设计 | 依据产品规划和业务约定，设计可执行的业务流程并评估合理性 |
| 测试用例设计 | 为已完成的流程设计正向、逆向和误操作用例 |
| 测试执行员 | 对运行中的应用执行用例，记录反馈与证据 |

派发任务时写明可操作进程、生产边界、受保护的身份与数据、意外写入的恢复方式，以及本阶段的交付要求。凭证按「凭证与数据」获取。发现执行偏差时，主 agent 修正前提或操作方法，再继续派发。

## 主流程

### 1. 建立测试依据

阅读确认范围内的变更、相关文件及其业务合同或说明，明确预期行为和不变量。后文统称这些依据为「业务约定」；约定未覆盖的行为记为观察。

完成标准：测试范围与业务依据明确，后续流程可据此判断预期。

### 2. 准备环境与设计流程

以下两项并行开展；已完成的流程可先进入用例设计。

- **环境准备**：环境搭建角色按「运行环境」准备隔离环境，提交就绪交接。
- **流程设计**：场景设计角色为每条业务写明操作者、前提、动作顺序、状态变化、可见结果和数据落点，标出流程依赖及共享状态，并在对应流程下记录设计疑点和观察。

完成标准：环境达到就绪条件；每条待测业务都有完整流程。两项分别验收。

### 3. 设计用例

为每条已完成流程设计用例，每条关联具体步骤，写明前提、操作和可判定的期望，覆盖相关不变量。

| 类型 | 验证重点 |
| --- | --- |
| 正向 | 流程完整走通，结果符合约定 |
| 逆向 | 前提不满足或操作被拒绝时，状态与反馈符合约定 |
| 误操作 | 按错、重复操作或穿插相邻动作时，业务仍保持其承诺的结果 |

完成标准：每条流程都有可判定的用例，每条用例都能追溯到流程步骤。

### 4. 执行与取证

主 agent 确认环境就绪、用例完成后，执行员对运行中的应用发起真实请求或操作，核对期望、实际反馈与持久化结果。界面操作遵循「界面验证」。

- 环境准备与用例执行分别记录；未就绪时说明阻塞及未执行范围。
- 需要临时日志锚点时，使用固定前缀，并注明覆盖范围及锚点之前的拒绝路径。
- 发现流程外的行为时，先补流程和用例，再执行。

完成标准：各用例均有结论与证据，未执行项有明确原因。

### 5. 报告与收尾

按「报告」汇总结果。环境搭建角色负责收尾，其他角色撤销各自引入的临时改动；无论测试完成还是中途终止，均执行以下清理并将结果补入总报告。

- 恢复测试数据；无法删除的新增数据予以停用，确认临时高权限身份已回收。
- 撤销临时源码改动和日志锚点，按原启动方式重启加载过锚点的测试进程，确认运行态已恢复。
- 删除含秘密的临时文件，保留测试产物。
- 停止本次启动且已无用途的进程；用户仍在使用的进程，先说明并取得确认。
- 代码提交由用户另行授权。

完成标准：报告包含结果、证据和收尾状态，遗留事项明确列出。

## 运行环境

### 隔离与操作边界

被测环境须运行用户确认的代码，并与真实用户使用的生产环境隔离。本地开发服务、沙箱、预览栈和独立测试实例均适用。

结合项目说明、启动命令、进程所属用户、监听端口和容器信息辨认环境：

| 对象 | 识别依据与操作边界 |
| --- | --- |
| 生产 | 对外服务、发布产物、正式数据、文档指定的正式入口，以及其他用户或特权账号启动的服务；保持进程与数据原状 |
| 被测应用 | 工作区代码、当前用户为本次开发启动的进程、文档指定的本地或沙箱入口；在确认范围内操作 |
| 共享基础设施 | 数据库、缓存、队列默认按共享资源处理；仅操作已确认隔离的测试数据，保留库及服务原状 |

环境归属或数据隔离不明确时，先请用户确认。新增基础设施、安装系统依赖或改变启动参数，也须先取得用户同意。

### 搭建与就绪交接

按项目现有说明搭建或复用环境，交接以下信息并归档证据：

- 启动命令、工作目录、运行用户、端口及访问入口。
- 可操作的具体进程和生产边界。
- 测试身份、数据使用方式及凭证配置来源，内容脱敏。
- 证明待测代码正在响应当前行为的真实请求及结果。

身份和数据可用、请求验证通过、交接信息齐全，视为环境就绪。

### 重启与编译

重启测试应用时，记录并沿用原启动命令、工作目录、运行用户和端口，精确定位目标进程，保留同组其他进程。重启后以真实请求验证待测行为；启动时间仅作辅助信息。

对于需要编译的入口，先请求预热，再按以下状态处理：

| 状态 | 判定 | 处理 |
| --- | --- | --- |
| 编译完成 | 日志确认本次编译完成，且对应响应包含预期内容 | 进入业务操作 |
| 加载中 | 编译尚未完成，页面停留在前一步、骨架或跳转状态 | 等待完成证据，单独记录环境状态 |
| 编译停滞 | 进程存活且空闲，日志持续停留在同次编译，响应持续为空，同进程已完成的其他入口仍可响应 | 停止该测试进程，清理其编译产物，按原方式重新启动 |

状态未明时，结合完成日志、进程活动和其他入口响应进一步判断。每份编译产物由单个开发进程写入；发生停滞后，下次测试使用重新生成的产物。页面源码调整安排在当前编译完成后。

业务动作后的页面切换，按目标入口判断加载状态。本机与代理浏览器表现不一致时，检查被测前端的编译和源站连接。

### 凭证与数据

- 从被测环境自身配置或环境变量读取凭证，测试夹具凭证仅用于其对应测试库。
- 派发说明与测试产物只记录凭证来源和脱敏信息。秘密确需落盘时，使用产物目录外、权限收紧的临时文件。
- 测试数据使用可识别前缀，事先明确恢复方式。受保护的写入意外成功时，立即恢复数据，再记录异常。

## 界面验证

使用当前环境中可用的浏览器；驱动依赖不足时，优先切换到已有可用浏览器。

- 等待目标控件可操作，结合当前界面语言、可见文案和控件上下文定位目标。
- 过滤与校验使用能触发真实输入事件的按键操作。
- 动作完成后立即读取提示并截图，再刷新核对界面与持久化结果；写入被拒绝时，确认控件恢复到操作前的值。
- 同时评估交互合理性；布局变更补充窄屏验证和截图。

完成的业务操作及其反馈才构成用例证据；加载画面归入环境状态。确认阻挡操作的是开发态错误浮层后，可关闭并继续测试；仅存在于开发态的浮层归入开发环境观察。

## 复测

沿用本轮已确认的范围；缺少范围时先确认。检查上一轮后的代码变化，按需更新流程及关联用例。

优先复测上次异常，再覆盖本次改动影响的路径。异常关闭须提供结果证据；界面异常同时核对界面与持久化状态。同一主题继续使用原产物目录。

## 报告

全部测试产物统一保存到 `/tmp/biztest-<主题>/`，总报告为 `report.md`。流程、用例、截图、日志摘录和其他辅证可单独成文，由总报告引用。语言与用户本轮对话一致。

### 异常分级

依据业务约定判定缺陷，未约定的行为保留为观察。

| 等级 | 含义 |
| --- | --- |
| P0 | 主路径不可用，或发生错误写入、删除、资金或权限问题，且无法可靠恢复 |
| P1 | 主路径违反业务约定，无可接受的绕过方式，操作者会据此做错 |
| P2 | 有明确绕过方式，或仅影响边界场景 |
| P3 | 文案、样式或提示不完整，业务结果正确 |

### 总报告模板

```markdown
# <主题>

## 过程
测试范围、业务依据、执行概况及生产边界遵守情况。

## 环境
负责人、搭建或复用方式、启动信息、访问入口、可操作进程、身份与数据使用方式、就绪交接及证据链接。存在阻塞时列出原因与未执行范围。

## 流程
业务流程及用例文档链接，包含流程依赖、设计疑点与观察。

## 结果
| 用例 | 所属流程及步骤 | 期望 | 实际 | 结论 | 证据 |
| --- | --- | --- | --- | --- | --- |

## 异常
按 P0 / P1 / P2 / P3 分组，无异常的等级写「无」。
每条说明操作与复现条件、界面反馈、实际数据、与预期的差异及证据。

## 收尾
负责人、数据恢复与身份回收、进程停止或保留情况、秘密文件删除、临时改动及运行态恢复结果，以及遗留事项。
```
