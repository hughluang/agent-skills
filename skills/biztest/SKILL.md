# 业务测试

用户说 biztest，或要求做真实业务测试时，按本 skill 执行。适用于当前工作区，不假设具体产品、端口或技术栈。

测试范围是最近集中变更的那一团代码，以及这团代码所办的业务。用户随这次调用说清了，就按他说的。没说清时，先指出这团变更和对应业务，请用户确认后再测。同一时段里彼此无关的变更不要并成一次。同一轮对话里已经确认过的范围可以沿用。

## 委派

进入主流程之前，请用户确认本次委派。预设四个角色：

- 测试环境搭建：负责环境全生命周期，包括辨认生产与被测环境、搭建或复用隔离环境、加载待测代码、准备凭证与测试数据、验证就绪、交接，以及测试结束后的恢复和清理
- 业务场景设计：业务场景的流程设计
- 测试用例设计：针对已完成流程的测试用例
- 测试执行员：按用例做真实业务测试

用户可以补充角色，也可以对某个角色不指派子 agent。每个指派的子 agent 确认使用的模型。用户确认前不开始主流程。同一轮对话里已经确认过的分配可以沿用。确认之后，主 agent 按这份分配委派；未指派子 agent 的业务，由主 agent 自己完成。

## 主流程

- 测试环境搭建与业务场景的流程设计并行：前者按「被测运行环境」准备并交接环境；后者遍历相关文件，按产品规划判断这套业务是否站得住，写成可跟着走的过程
- 针对已完成的流程设计测试用例：按测试判断正向、逆向和误操作，每条写明期望
- 环境就绪且用例完成后，才进行真实业务测试，检查动作反馈、日志（可以临时插入锚点输出跟踪信息）等信息是否符合预期
- 如果涉及UI测试，应配合截图观测，除了程序BUG还需关注交互是否合理
- 测试环境搭建角色负责最终恢复和清理；其他角色配合撤销自己引入的临时改动

## 产出

一次测试的全部产物集中在「报告」规定的目录。总报告要说明过程和辅证，并标出异常。

## 异常等级含义

P0:主路径不可用，或写错、删错、资金或权限出错，且不能可靠恢复
P1:主路径和合同不一致，没有可接受的绕过，操作者会据此做错
P2:有明确绕过（刷新、换页、看说明），或只影响边界
P3:文案、样式、提示不完整，结果本身是对的

## 派发说明

说明里写清：

- 只许动哪些进程，生产是什么
- 凭证从项目自己的配置或环境变量读，不写进说明，也不许用测试夹具里的密码顶替
- 哪些身份和数据禁止改坏；改坏了如何立刻恢复
- 这一阶段要交回的期望、实际和辅证

用错凭证、停在加载、或动了禁止项时，主 agent 纠正后续跑。不要把同一份说明原样再派一次。

## 步骤

1. 范围确认之后，再看这团变更，读它所依据的合同或说明。合同没写的行为标成观察，不升成缺陷。
2. 环境准备。测试环境搭建角色按「被测运行环境」搭建或复用环境，完成就绪交接；本步与第 3 步并行，不阻塞基于已完成流程的用例设计。
3. 流程设计。按产品规划看这团变更和它所依据的合同，把要测的业务写成可跟着走的过程：谁在什么前提下做什么，状态怎么变，做完操作者看到什么、数据落在哪里。过程之间的先后和共享状态标出来。设计上站不住的记在对应过程旁边；合同没写的行为沿用第 1 步，标成观察。这一段完成的标准是：每条要测的业务都有一条写完的过程。还没有过程的业务，不进入下一段。
4. 测试用例。只针对上一段交回的过程来写，按测试判断对错。每条用例挂在过程中的一步上，并写明期望。正向是这条过程走通；逆向是前提不满足或中途被拒绝时过程怎么走；误操作是操作者按错、重复、或插进相邻动作时，过程是否仍守住它声称的结果。改动声称要守住的不变量，写进对应用例。过程里没有的行为，不单开用例。这一段完成的标准是：每条过程都有能判定对错的用例，每条用例都能指回过程中的一步。
5. 真实执行。主 agent 确认第 2 步环境就绪且第 4 步用例完成后，测试执行员才按用例对运行中的应用做真实请求和真实操作。环境未就绪时如实记录阻塞，不把准备尝试算成已执行用例。临时锚点用固定前缀，并记下哪些拒绝发生在锚点之前所以不会有日志。界面要等真正的操作出现再点；截一张加载中的图不算测完。保存后立刻看反馈，再核对刷新后的界面和持久化结果。拒绝写入后，控件应回到保存前的值，不能只信提示。跑的时候发现过程没写到的行为，先补过程再补用例，不临场加一条没有期望的操作。
6. 把总报告写入产物目录。异常按上面四个等级标出；没有就写无。
7. 清理。测试环境搭建角色负责收尾，其他角色配合撤销自己引入的临时改动；即使环境准备或测试中途失败，也清理本次已产生的改动。删掉锚点，并重启加载过锚点的进程，使运行中的代码不再打这些日志。不要改它的启动参数。删掉秘密文件。产物目录留下。测试数据能恢复就恢复，不能删除就停用，不要多留一个活跃的高权限身份。停掉本次拉起、测完不再需要的进程。用户还在用的进程先说明再停。生产始终不动。没有用户要求就不要提交。收尾完成后，将恢复和清理结果补入总报告。

## 被测运行环境

本地开发服务、沙箱、预览栈、和正式环境分开的测试实例，都按同一套处理。名字不重要。它要同时满足：跑的是用户确认的那份代码，并且和真实用户正在用的生产分开。

### 搭建与交接

测试环境搭建角色可按项目既有说明搭建或复用隔离测试环境，并按下文完成进程、凭证和测试数据准备。需要新增基础设施、安装系统依赖、改变启动参数，或无法确认数据隔离时，先请用户决定；界面测试仍遵守「界面」中的浏览器依赖限制。

就绪交接要给出：启动命令、工作目录、运行用户、端口与访问入口；允许操作的具体进程及生产边界；测试身份和数据的使用方式、凭证配置来源（不含秘密）；证明待测代码正在响应当前行为的真实请求及辅证。所需身份和数据可用、请求验证通过且上述信息齐全，才算环境就绪。环境准备及交接证据按「报告」归档。

### 分开

从当前项目的启动说明、进程、监听端口、容器名和所属用户来认，不凭端口号习惯。

- 生产：对外服务、发布产物、正式数据、别的用户或特权账号拉起的、文档写明的正式入口。整次测试不重启、不停止、不改它的数据。
- 被测环境：工作区代码、当前用户为这次开发拉起的进程、文档写明的本地或沙箱入口。只重启这一类。
- 数据库、缓存、队列默认是共享基础设施。可以重启应用进程，不清库、不改生产数据。
- 分不清属于哪一类时停下来问。不要猜。

### 重启

记下原命令、工作目录、运行用户和端口，用同一条命令拉起。不要另加热重载、更换打包器或改端口。只有不这样改，新代码就进不去时，才提出调整，取得用户确认后执行，并在报告里写明原因。

只结束具体 pid。开发服务的父进程可能和当前 shell 属于同一进程组，按进程组结束会把 shell 一起停掉。

重启后用一次真实请求证明新代码已在响应当前行为。进程启动时间晚于文件修改，还不能说明加载的是新代码。

### 加载和卡住

骨架、跳转、首次编译是加载。对照服务日志：日志停住且响应一直是空，才是卡住。本机浏览器正常、代理里的浏览器一直加载时，先查被测前端的编译和它连的源站，不要去重启生产。

开发态错误浮层会挡住点击。确认是浮层后再关掉。生产构建里没有这层，就不记成产品缺陷。

### 凭证和数据

登录凭证读被测环境自己的配置。测试夹具里的密码只属于测试库。秘密不写入产物目录，也不写进交给子 agent 的说明。必须落盘时另放权限收紧的临时文件，测完删除。

测试数据用可识别的前缀。结束时恢复原状；产品不允许删除就停用。不要多留一个活跃的高权限身份。被保护的写入若意外成功，立刻恢复，再记缺陷。

### 界面

用当前环境里真能打开的浏览器。驱动库缺系统依赖时，改用已经能用的浏览器，不为了这次测试新装一套。

等真正的操作出现再点。页面上同名的导航会先被点到。程序化填入不一定触发输入事件；过滤和校验用真实按键。可访问名称用当前界面语言里看得见的文案。

提示会自己消失。动作一完成就读提示文本，再截图，然后核对刷新后的界面和持久化结果。布局有变化时看窄屏会不会溢出，不要只留一张桌面图。

## 复测

用户说再测试时，沿用这次对话里已经确认的范围。范围不在这次对话里、用户也没重说，就先确认。确认后再看被测文件在上一轮之后有没有变。过程变了就先改流程，再改挂在上面的用例。先复测上一份报告里的异常，再测这次改动会碰到的路径。异常消失要写出界面和持久化两侧的证据。不要把整份矩阵无差别重跑一遍，也不要跳过上次失败的那条。

## 报告

一次测试的产物目录是 `/tmp/biztest-<主题>/`。报告、流程、用例、截图、日志摘录和其他辅证都放在这个目录里，不写到目录外。总报告是其中的 `report.md`。界面和接口可以另写文件，仍放在该目录，并由总报告引用。同一主题的复测继续写入这个目录。语言与用户这次对话一致。不写密码、cookie、令牌或其他秘密。

```markdown
# <主题>

## 过程
测了什么、动了哪些进程、生产未动。

## 环境
由谁负责、搭建还是复用、启动方式与访问入口、可操作进程及生产边界、身份与数据使用方式（不含秘密）、就绪请求和交接辅证；未就绪时写明阻塞及未执行范围。

## 流程
每条业务过程写清前提、动作顺序、状态变化、做完操作者看到什么、数据落在哪里。设计上站不住的和标成观察的，记在该过程下。

## 结果
| 用例 | 所属过程 | 期望 | 实际 | 结论 |
| --- | --- | --- | --- | --- |

## 异常
### P0 / P1 / P2 / P3
每条写：操作者看到什么，数据实际是什么，怎样才能对上。
没有的等级写「无」。

## 收尾
由谁完成收尾、恢复了什么、停用了什么、停掉或保留了哪些进程、秘密文件是否已删除、锚点是否已从运行中的进程去掉，以及未能恢复的事项。
```
