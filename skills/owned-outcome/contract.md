# Delegation Contract

每次委派给子代理的提示都包含以下各段。结构写死，内容按单元填写。子代理看不到 planner 的上下文，契约必须自足。

## 共用尾段

每份契约末尾都附上这些段：

```
## Predecessor
<前任交接文档路径>。先读它，从其 Next 段继续；已完成的部分先在工作区核实。
（仅接替中断的子代理时包含本段。）

## Files
你拥有 <文件/目录>。<共享文件> 只允许局部定点编辑。<文件> 由同时运行的其他子代理拥有，不要修改。
（researcher 不含本段。）

## Handoff
按 <本技能目录绝对路径>/handoff.md 中 <角色> 的骨架，把交接文档写到 <交接文档绝对路径>。这是你唯一的实质产出通道：planner 和后续代理只读这份文档与工作区。提前停下也先把它写好。

## Report
交接文档写好后，只回报一行：`<Status> <交接文档绝对路径>`；blocked 时追加一句阻塞原因。
```

## Executor 契约

```
## Ticket
<工单文件路径>。先完整阅读它。

## Rules
- 仓库规则：<AGENTS.md / 开发文档路径>，开工前阅读。
- 已安装 `tdd` 则遵循它。未安装时：先写一个失败的测试，再写刚好让它通过的实现；测试观察公开行为，期望值来自工单或 spec，不从实现反推；一次只做一条切片。没有可测接缝的部分（纯配置、文档）用下方验证命令兜底。
- 可复用的既有实现：<路径 + 一句用途>。优先复用，不另造。

## Scope
- 本单元交付：<一句结果描述>。
- 不在本单元范围：<相邻工单负责的部分>。

## Constraints
- 严禁执行任何 git 写操作（add、commit、stash、checkout、reset 等）。
- <语言、命名、注释等仓库特有约束>

## Verification
完成前运行并全部通过：
<命令 1>
<命令 2>
若某失败看起来与本单元无关，记录命令与输出，不要去修。

<共用尾段，角色 executor>
```

## Reviewer 契约

```
## Target
本批单元（逐张工单列出）：
- <工单路径 1>：executor 交接文档 <路径>
- <工单路径 2>：executor 交接文档 <路径>
先读每份交接文档：Changes 段是该单元的改动范围，Decisions 段说明有意为之的设计，Review focus 段是重点位置。改动本身以工作区为准。

## Task
对上述全部改动执行 `review-substance` 技能，直接在代码中修复发现的问题。该技能未安装时，Status 写 blocked 并停下，不要转述它的规则来代替。范围限于这些改动及其直接调用方。
同时检查跨单元问题：同批单元之间重复的 helper、互相冲突的约定、本应共用却各写一份的实现。

## Constraints
- 严禁执行任何 git 写操作。
- 不改变工单规定的产品行为；对行为有疑问时写进 Doubts，不修改。

## Verification
修复后运行每张工单的验证命令：
- <工单 1>：<命令>
- <工单 2>：<命令>

<共用尾段，角色 reviewer>
```

## Researcher 契约

```
## Question
<要回答的具体问题，以及它服务于 spec 的哪一部分>

## Scope
只读，交接文档除外。调研范围：<目录/模块>。

<共用尾段，角色 researcher>
```
